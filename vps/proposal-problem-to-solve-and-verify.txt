VPS utilities — scope and acceptance criteria

Request: add four scripts under vps/ in the repository. PR #8 is merged; use a new vps-tools branch and a new pull request based on main.
1. enable-ssh.sh: exactly five physical lines; enable and start OpenSSH using the installed systemd service/socket units; fail on errors.
2. disable-ssh.sh: exactly five physical lines; stop and disable SSH listeners, including socket activation; fail on errors.
3. check-ssh-config.sh: read-only SSH configuration audit. Report OS/version, password authentication, public-key authentication and whether a key is required, root login policy, and user/group allow/deny rules. Show configuration paths and line numbers, distinguish effective settings from declarations, and account for Include and Match through OpenSSH's own parser. Provide connection-context options for VPS-specific configurations.
4. install-tools.sh: apt-get installation of a documented, useful Debian/Ubuntu administration tool set. Support package preview; fail on installation errors; perform no full system upgrade.

Interpretation: the authentication/root/account phrases specify audit questions. The audit reports their values; it does not rewrite SSH authentication policy.
Scope: create scripts and documentation in vps/, preserve existing VPN work, create a reviewable pull request without merging. Do not run SSH start/stop or package installation against the workspace host.
Verification: exact line counts, shell syntax, mocked systemctl behavior for ssh/sshd and socket activation, OpenSSH parser fixtures for Include/Match/defaults/authentication alternatives/source lines, and mocked apt argument/error checks.
Review: two independent reviewers check request-to-proposal and evidence-to-proposal, followed by a second independent review round after corrections. Record findings and resolutions in evidence-and-content.txt.

Round 1 refinements:
- Preserve an active service's activation mode; select a socket when active or when the service is stopped. Disable boot activation before stopping installed SSH services and sockets in one transaction. Ignore alias rows; fail on ambiguous service selection, masked-unit action errors, and empty discovery.
- Use sshd -ddd -T -C with explicit connection context. Effective stdout is authoritative. For provenance, use first active scalar event in the Match pass, then global pass; accumulate allow/deny list events from the applicable pass. Mark compiled defaults and command-line overrides.
- Report AllowUsers/DenyUsers/AllowGroups/DenyGroups as configuration rules. Distinguish PermitRootLogin from root-exclusive AllowUsers. Key requirements include alternative authentication chains, keyboard-interactive, GSSAPI, host-based authentication, and root restrictions.
- Apt --list and --dry-run perform no package-index update or install. Use apt-get update before installation, --no-install-recommends, and failure propagation.

Round 2 refinements: disable-before-stop completes boot configuration before a control-group stop can terminate the caller. SSH password and keyboard-interactive/PAM are reported as distinct methods; disabled PAM devices are excluded when evaluating key requirements on Linux.

Acceptance checkpoint: all four scripts and usage documentation exist. Both SSH control scripts have five lines. Twelve test methods pass with real OpenSSH parser fixtures and isolated systemctl/apt mocks. Two independent round-3 reviewers approved the defined scope after reviewing the request, proposal, implementation, documentation, and evidence. Release action: commit vps/ on a new branch and open a pull request against main.
